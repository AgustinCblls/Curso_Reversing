C y Python mínimos para analizar

Principiante Ruta 1 · Fundamentos (Obligatoria)

Objetivo de la lección

Al terminar vas a poder leer y escribir programas chicos en C (variables, condiciones, bucles, funciones, punteros) y en Python (tipos, listas, funciones, archivos binarios), compilarlos, ejecutarlos en el laboratorio y usarlos como conejillos de indias para el debugger.

Prerrequisitos: Etapa 0 y las lecciones anteriores de la Etapa 1. Duración sugerida: 8 a 10 horas. Estimación aproximada.

Antes de empezar: qué sirve y qué no del material clásico de Python

Si te cruzaste con la carpeta Python ISO video tutes del material clásico, tené en cuenta que no es un curso de Python. Son 55 clases de lógica y fundamentos de programación (dictadas por Daniel Bermúdez, con pseudocódigo y ejemplos en Basic, Pascal y C) grabadas en 2007, cuando la versión vigente era Python 2.5.1. No contienen código Python ejecutable, y la segunda parte que anuncian, con Python "puro", no está en la carpeta.

Eso no lo vuelve inútil. Lo que sí enseña —algoritmos, secuencia, decisión, ciclos, arreglos, matrices y funciones— es una buena base mental para programar, así que podés mirarlos por la lógica. Para la sintaxis, esta lección usa Python 3 y C estándar, con recursos externos actuales que se indican abajo.

El subconjunto de C que vas a leer en un debugger

No necesitás ser experto en C. Necesitás reconocer cinco construcciones:

  1. Variables y tipos: int, char, unsigned, punteros (int *p).
  2. Condiciones: if, else, switch.
  3. Bucles: for, while.
  4. Funciones: parámetros, valor de retorno, variables locales.
  5. Punteros y arrays: &x (dirección de), *p (contenido de), a[i].

Ejemplo paso a paso: el programa del capítulo 15

El capítulo 15 analiza un crackme de práctica que pide dos números. La lógica que Ricardo deduce del listado es:

  • el primer número tiene que ser menor o igual que 0x32 (50 decimal);
  • el segundo tiene que ser mayor o igual que 0x32;
  • la suma de los dos, multiplicada por 4, tiene que dar 0x1E0 (480 decimal).

Un programa equivalente, escrito por vos, es este:

#include <stdio.h>

int main(void) {
    int a, b;
    printf("Primer valor: ");
    if (scanf("%d", &a) != 1) return 1;
    printf("Segundo valor: ");
    if (scanf("%d", &b) != 1) return 1;

    if (a > 50 || b < 50) {
        puts("No cumple las condiciones");
        return 0;
    }
    if ((a + b) * 4 == 480) {
        puts("Correcto");
    } else {
        puts("Incorrecto");
    }
    return 0;
}

Cómo se lee, línea por línea:

  • int a, b; reserva dos enteros en el stack.
  • scanf("%d", &a) lee un decimal y lo guarda en la dirección de a. El & es la dirección; sin él, la función no podría modificar la variable.
  • a > 50 || b < 50 usa || (OR lógico): si cualquiera de las dos condiciones se cumple, rechaza.
  • (a + b) * 4 == 480 reproduce la comparación del binario. Con a = 40 y b = 80, da (120) * 4 = 480, así que imprime Correcto.

Compilación (en el guest, con el compilador que instalaste en el Paso 3 de la lección 0.1):

gcc -O0 -g -o check.exe check.c

-O0 desactiva optimizaciones para que el assembly sea fácil de seguir; -g agrega información de depuración. En Visual Studio, compilá en modo Debug.

Qué mirar en el debugger: el if (a > 50 || b < 50) se convierte en dos comparaciones y saltos; el (a+b)*4 se convierte en un add seguido de un shl eax, 2 (desplazar dos bits a la izquierda es multiplicar por 4). Eso conecta directo con la lección de instrucciones.

Cómo se ven los datos de C en memoria

Las cinco construcciones de arriba alcanzan para seguir el flujo de un programa. Para entender sus datos hacen falta algunas más. El criterio es el mismo: no hace falta dominarlas, hace falta reconocer qué deja cada una en el binario. Al final de la sección hay un programa que las junta todas para que las compruebes.

Dónde vive cada variable

Según cómo se declara, una variable termina en un lugar distinto del proceso, y ese lugar define cómo se la accede en assembly:

Declaración Dónde vive Cómo se accede Cuánto dura
Local: int x; dentro de una funciónStack[ebp-N] o [rsp+N]Hasta que la función retorna
Global con valor: int g = 5;Sección .dataDirección fija: [0x403000] en 32 bits, relativa a RIP en 64Todo el proceso
Global sin valor: int g;.bss (GCC) o la parte final de .data (MSVC); arranca en cero y no ocupa lugar en el archivoIgual que la anteriorTodo el proceso
Constante o literal: "hola", const int k = 7;.rdata (solo lectura)Igual que una globalTodo el proceso
Local static: static int n; dentro de una función.data o .bss, no el stackIgual que una globalTodo el proceso: conserva el valor entre llamadas
Dinámica: p = malloc(16);HeapA través del puntero: [eax], [eax+4]Hasta el free

Dos cosas que se desprenden de la tabla. Primero, una variable local static es, para el binario, una global: la palabra solo limita desde dónde se la puede nombrar en el fuente. Segundo, en const char *mensaje = "hola"; hay dos datos: los cinco bytes de la cadena, en .rdata, y el puntero mensaje, en .data, que contiene la dirección de la cadena. Esa indirección es la razón por la que a veces la referencia a una cadena no lleva directo al código que la usa.

Estructuras: campos en offsets fijos

Una struct agrupa varios datos en un bloque continuo. Cada campo queda a una distancia fija del inicio (su offset), y el compilador intercala bytes de relleno (padding) para que cada campo empiece en una dirección múltiplo de su tamaño:

struct registro {
    char  tipo;       /* offset 0, 1 byte                        */
                      /* offsets 1 a 3: relleno                  */
    int   id;         /* offset 4, 4 bytes                       */
    short len;        /* offset 8, 2 bytes                       */
    char  nombre[8];  /* offset 10, 8 bytes                      */
                      /* offsets 18 y 19: relleno final          */
};                    /* sizeof = 20                             */

En el binario no queda ningún nombre: r->id es [eax+4] y r->len es word ptr [eax+8]. Reconstruir una estructura es hacer el camino inverso: juntar todos los accesos del tipo [registro+constante] que usan el mismo puntero, anotar offset y tamaño de cada uno, y armar la tabla. La lección 2.7 muestra cómo cargarla en el desensamblador para que el listado pase a mostrar nombres de campos.

Uniones: los mismos bytes vistos de otra forma

Una union se declara igual que una estructura, pero todos sus campos empiezan en el offset 0 y comparten los mismos bytes. Su tamaño es el del campo más grande. No convierte nada: reinterpreta.

union vista {
    unsigned int  u;      /* los 4 bytes como entero            */
    float         f;      /* los mismos 4 bytes como flotante   */
    unsigned char b[4];   /* los mismos 4 bytes, uno por uno    */
};

union vista v;
v.u = 0x3F800000;
/* ahora v.f vale 1.0  y  v.b es  00 00 80 3F  (little-endian) */

En assembly una unión es invisible: solo se ve que la misma dirección se lee a veces como 4 bytes enteros, a veces con una instrucción de punto flotante, a veces byte por byte. Si al reconstruir una estructura encontrás que un mismo offset se usa con tamaños o tipos incompatibles, probablemente sea una unión. Windows las usa mucho; la más común es LARGE_INTEGER, un número de 64 bits que también se puede leer como dos mitades de 32 (LowPart y HighPart).

Campos de bits y flags

Para guardar varios datos chicos en un solo entero hay dos estilos. El primero es declarar campos de bits, indicando cuántos bits ocupa cada uno:

struct estado {
    unsigned int listo : 1;   /* bit 0          */
    unsigned int modo  : 3;   /* bits 1 a 3     */
    unsigned int nivel : 4;   /* bits 4 a 7     */
};

Con listo = 1, modo = 5 y nivel = 9, el entero completo vale 1 + (5 << 1) + (9 << 4) = 1 + 10 + 144 = 0x9B. El compilador genera por su cuenta los desplazamientos y máscaras; leer e.modo se convierte en algo como:

mov eax, [rbp-0x14]   ; el entero que contiene los tres campos
shr eax, 1            ; descarta el bit de 'listo'
and eax, 7            ; se queda con 3 bits: el valor de 'modo'

El segundo estilo, que es el que usa la API de Windows, es declarar constantes con un bit cada una y combinarlas a mano con |, & y ~:

#define OPC_LECTURA   0x01
#define OPC_ESCRITURA 0x02
#define OPC_OCULTO    0x04

unsigned opciones = OPC_LECTURA | OPC_OCULTO;   /* 0x05          */
if (opciones & OPC_ESCRITURA) { /* ... */ }     /* consultar     */
opciones &= ~OPC_OCULTO;                        /* apagar: 0x01  */

En el binario los dos estilos se ven igual: and, or, test y desplazamientos con constantes. Cómo leerlos está desarrollado en la sección de máscaras de bits de la lección 2.2.

Enumeraciones

Un enum le pone nombre a una lista de enteros consecutivos: en enum color { ROJO, VERDE, AZUL };, ROJO vale 0, VERDE 1 y AZUL 2. Los nombres existen solo en el fuente. En el binario if (c == AZUL) es cmp eax, 2, y nada indica que ese 2 tuviera nombre. Cuando una variable se compara contra varios números chicos y consecutivos, o entra a un switch, lo más probable es que fuera una enumeración; ponerle nombres a esos valores en el desensamblador es de lo que más aclara un listado.

Punteros a función

Una variable puede guardar la dirección de una función, y el programa puede llamarla a través de esa variable:

int suma(int a, int b)  { return a + b; }
int resta(int a, int b) { return a - b; }

int (*op)(int, int) = suma;      /* 'op' guarda la direccion de suma       */
int r = op(7, 3);                /* llama a lo que 'op' apunte: 10         */

int (*tabla[2])(int, int) = { suma, resta };
r = tabla[1](7, 3);              /* elige la funcion por indice: 4         */

En assembly, una llamada normal es un call con el destino a la vista. Una llamada por puntero es un call indirecto: call rax, call qword ptr [rbp-0x20] o, con una tabla, call qword ptr [rax+rcx*8]. La diferencia para el análisis es grande: mirando solo esa instrucción no se sabe a dónde va. Hay que averiguar qué se guardó en el puntero (análisis estático hacia atrás) o poner un breakpoint y mirar el registro (análisis dinámico).

Los punteros a función están en todas partes aunque no los escribas vos:

  • Callbacks: le pasás a una API la función que querés que llame. CreateThread recibe la función del hilo (lo viste en 1.3); qsort recibe la que compara; EnumWindows, la que procesa cada ventana. Cuando el argumento de una API es una dirección dentro de .text, es un callback, y ahí hay código que vale la pena mirar.
  • La IAT: es una tabla de punteros a función que llena el loader (lección 1.6).
  • Las vtables de C++: tablas de punteros a función, una por clase, para los métodos virtuales (lecciones 2.4 y 2.18).
  • Tablas de despacho: un arreglo de funciones indexado por un número de comando. Es una alternativa al switch, y la base de las máquinas virtuales de la lección 2.26.

Ejemplo paso a paso: todos los datos en un programa

Este programa declara una variable de cada tipo y muestra tamaños, offsets y valores. Guardalo como datos.c:

#include <stdio.h>
#include <stddef.h>
#include <string.h>

struct registro { char tipo; int id; short len; char nombre[8]; };
union  vista    { unsigned int u; float f; unsigned char b[4]; };
struct estado   { unsigned int listo : 1; unsigned int modo : 3; unsigned int nivel : 4; };
enum   color    { ROJO, VERDE, AZUL };

int global_ini = 0x11223344;
int global_cero;
const char *mensaje = "hola";

int suma(int a, int b)  { return a + b; }
int resta(int a, int b) { return a - b; }

int contador(void) {
    static int veces = 0;
    return ++veces;
}

int main(void) {
    int local = 5;
    union vista v;
    struct estado e;
    unsigned int crudo = 0;
    enum color c = AZUL;
    int (*tabla[2])(int, int) = { suma, resta };

    printf("registro: sizeof=%u offsets=%u %u %u %u\n",
           (unsigned)sizeof(struct registro),
           (unsigned)offsetof(struct registro, tipo),
           (unsigned)offsetof(struct registro, id),
           (unsigned)offsetof(struct registro, len),
           (unsigned)offsetof(struct registro, nombre));

    v.u = 0x3F800000;
    printf("union: f=%f bytes=%02x %02x %02x %02x\n", v.f, v.b[0], v.b[1], v.b[2], v.b[3]);

    memset(&e, 0, sizeof e);
    e.listo = 1; e.modo = 5; e.nivel = 9;
    memcpy(&crudo, &e, sizeof e);
    printf("campos de bits: crudo=0x%08x\n", crudo);

    printf("enum: AZUL=%d\n", (int)c);
    printf("punteros a funcion: %d %d\n", tabla[0](7, 3), tabla[1](7, 3));

    contador(); contador();
    printf("static: contador=%d\n", contador());

    printf("local=%p global_ini=%p global_cero=%p\n",
           (void *)&local, (void *)&global_ini, (void *)&global_cero);
    printf("mensaje=%p (el puntero esta en %p)\n", (void *)mensaje, (void *)&mensaje);
    return 0;
}

Qué tiene que imprimir. Las primeras seis líneas son iguales en cualquier compilador de Windows para x86 o x64:

registro: sizeof=20 offsets=0 4 8 10
union: f=1.000000 bytes=00 00 80 3f
campos de bits: crudo=0x0000009b
enum: AZUL=2
punteros a funcion: 10 4
static: contador=3

Las dos últimas muestran direcciones, que cambian en cada ejecución por el ASLR. Lo que hay que comparar es su forma: la de local es claramente distinta (está en el stack, lejos de todo), mientras que global_ini, global_cero, la cadena y el puntero mensaje están cerca entre sí, dentro de la imagen del .exe, pero no pegadas: caen en secciones distintas.

Qué mirar en el debugger. Con el programa detenido en main:

  • Seguí en el volcado la dirección de global_ini: vas a ver 44 33 22 11, el valor inicial en little-endian. Buscá después esos mismos bytes en el archivo con el editor hexadecimal: están, porque .data se guarda en disco.
  • Ubicá en el mapa de memoria (o en el visor de PE) a qué sección pertenece cada una de las cuatro direcciones.
  • Encontrá la llamada tabla[0](7, 3). No es un call suma: es un call a un registro o a una posición de memoria. Mirá de dónde sale ese valor.
  • Encontrá la lectura de e.modo o las escrituras de los tres campos: instrucciones and, or y desplazamientos sobre la misma posición del stack.

El subconjunto de Python que vas a usar como herramienta

Python no compila a un .exe nativo (en el sentido clásico), así que no es el lenguaje que vas a ver en un debugger de Windows. Es la navaja suiza para procesar archivos, calcular hashes, parsear cabeceras y automatizar tareas.

Ejemplo: leer los primeros bytes de un ejecutable

from pathlib import Path

data = Path("check.exe").read_bytes()
print("Tamaño:", len(data))
print("Primeros dos bytes:", data[:2])          # b'MZ'
print("Primeros 16 bytes:", data[:16].hex(" "))

Salida esperada (los valores exactos dependen del compilador):

Tamaño: 53248
Primeros dos bytes: b'MZ'
Primeros 16 bytes: 4d 5a 90 00 03 00 00 00 04 00 00 00 ff ff 00 00

read_bytes() devuelve un objeto bytes: una secuencia inmutable de valores entre 0 y 255. data[:2] toma los dos primeros; .hex(" ") los muestra en hexadecimal separados por espacios. No hace falta instalar nada.

Ejemplo: calcular un SHA-256

import hashlib
from pathlib import Path

datos = Path("check.exe").read_bytes()
print(hashlib.sha256(datos).hexdigest())

Ese hash es el mismo que devuelve Get-FileHash en PowerShell. Sirve para la bitácora de la Etapa 0.

Ejemplo: desempaquetar un entero con struct

Los bytes sueltos no alcanzan: para leer una cabecera hay que interpretar grupos de bytes como números. Eso lo hace el módulo struct. En un PE, en el offset 0x3C hay un entero de 4 bytes (little-endian) que apunta a dónde empieza la firma PE\0\0:

import struct
from pathlib import Path

data = Path("check.exe").read_bytes()
(pe_off,) = struct.unpack_from("<I", data, 0x3C)   # "<I" = entero de 4 bytes, little-endian
print("La cabecera PE empieza en:", hex(pe_off))
print("Firma en ese offset:", data[pe_off:pe_off+4])  # b'PE\x00\x00'

struct.unpack_from("<I", data, 0x3C) lee 4 bytes desde el offset 0x3C y los arma como un entero sin signo (I) en little-endian (<). Esto conecta directo con la lección de PE: lo que ahí leés a mano, acá lo automatizás.

Ejemplo: el mismo cálculo del crackme, en Python

a = int(input("Primer valor: "))
b = int(input("Segundo valor: "))
if a <= 50 and b >= 50 and (a + b) * 4 == 480:
    print("Correcto")
else:
    print("Incorrecto")

Compará las dos versiones: en C el scanf recibe una dirección; en Python input() devuelve un string y int() lo convierte. En C la condición se escribe con || y &&; en Python, con or y and. La lógica es la misma.

Python 2 vs Python 3

Si encontrás material viejo con print "hola" o raw_input, es Python 2. Hoy se usa Python 3: print("hola"), input(), divisiones con / que devuelven float y // para entero. Parte del material clásico es de esa época: si lo consultás, no copies esa sintaxis.

Hacia dónde sigue este camino

No hace falta parsear cada cabecera a mano con struct: hay librerías que ya lo hacen. El camino natural desde acá es:

  1. pefile — lee cabeceras PE, secciones e imports de un ejecutable de Windows con unas pocas líneas.
  2. capstone — desensambla bytes a instrucciones x86/x64 desde Python.
  3. IDAPython / Ghidra scripting — automatizar el análisis dentro del desensamblador.

Esos tres se desarrollan, con ejemplos, en la rama de automatización de la Etapa 5. Lo de esta lección —bytes, hex, struct, archivos— es la base que te deja usarlos sin que sean magia.

  4. Escribí un script en Python que recorra una carpeta, calcule el SHA-256 de cada archivo y escriba un CSV con ruta,hash. Usalo sobre tu carpeta de prácticas.
  5. Modificá el script para que lea la cabecera PE y muestre ImageBase y AddressOfEntryPoint (podés reutilizar el de la lección de PE). Usá struct.unpack_from sobre los offsets correctos.

  9. Sin compilar: calculá el sizeof y los offsets de struct s { char a; char b; int c; char d; };. Después reordená los campos para que ocupe lo menos posible.
  10. Sin compilar: en struct estado, ¿cuánto vale el entero completo con listo = 0, modo = 7 y nivel = 2? ¿Qué instrucciones extraerían nivel?
  11. En datos.c, cambiá tabla[0](7, 3) por tabla[local % 2](7, 3), compilá y encontrá el call en el debugger. ¿Qué función se llama, y cómo lo comprobás sin leer el fuente?
Ver las respuestas de los ejercicios 9 a 11

9. a en el offset 0, b en 1, relleno en 2 y 3, c en 4, d en 8, relleno de 9 a 11: sizeof = 12. Poniendo el int primero (c, a, b, d) quedan los offsets 0, 4, 5 y 6 y un solo byte de relleno al final: sizeof = 8.

10. 0 + (7 << 1) + (2 << 4) = 14 + 32 = 46 = 0x2E. Para extraer nivel: shr eax, 4 y después and eax, 0xF.

11. local vale 5 y 5 % 2 = 1, así que se llama a tabla[1], que es resta, y el resultado es 4. Para comprobarlo sin el fuente: breakpoint en el call indirecto, mirar el valor del registro o de la posición de memoria que usa como destino, y seguir esa dirección en el desensamblador (o entrar con F7). La función a la que llegás hace un sub.

Preguntas de repaso

1. ¿Por qué scanf necesita &a y printf no? Porque scanf tiene que escribir en la variable, y para eso necesita su dirección. printf solo lee el valor.

2. ¿Qué diferencia hay entre int y unsigned int? El rango y la interpretación. int usa complemento a dos e incluye negativos; unsigned int solo representa valores no negativos y puede llegar al doble del máximo positivo.

3. ¿Por qué x << 2 equivale a multiplicar por 4? Porque cada desplazamiento a la izquierda multiplica por 2. Dos desplazamientos multiplican por 4. Es la operación que usa el compilador para optimizar multiplicaciones por potencias de dos.

4. ¿Python sirve para analizar un .exe? Sí, como herramienta: leer bytes, parsear cabeceras, calcular hashes, automatizar. No es el lenguaje del binario que analizás, salvo que el programa esté hecho en Python y empaquetado con un generador de ejecutables.

5. ¿Los tutoriales tradicionales de lógica enseñan Python moderno? No. Enseñan lógica de programación con pseudocódigo y ejemplos en Basic, Pascal y C. Son útiles como base mental, pero no reemplazan un curso de Python 3 moderno.
